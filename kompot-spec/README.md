# kompot-spec

Спецификация провода: генератор JSON Schema, валидатор и spec-модуль каждого протокольного модуля.
Нормативный текст — в [SPEC.md](SPEC.md), он адресован тому, кто пишет сервер на другом стеке;
здесь — только как этим пользоваться из Kotlin.

## Схемы из тех же дескрипторов

Схема каждого протокольного модуля строится из тех самых `SerialDescriptor`, которыми
kotlinx.serialization кодирует ответ, поэтому отстать от типов молча она не может. Сгенерированные
файлы закоммичены в [`schema/`](schema); то, чего схема выразить не может — деградация, два вида
расширяемости, связность формы, пагинация, транспорт, — записано в SPEC.md.

Закрытый список типов — свойство **сборки**, а не тулкита: приложение собирает свою спецификацию из
этих модулей и своих и получает свой профиль. Тринадцать схем тулкита и профиль рядом с ними
выходят байт-в-байт одинаковыми при любом способе сборки.

```kotlin
val schemas = KompotSpec.generateAll(KompotToolkitSpec.modules + myComponentsSpecModule())
val profile = KompotSpec.profile(schemas)
```

## Правила едут в артефакте

Схемы и сам SPEC.md лежат в опубликованном артефакте: правило §9 несёт id, на который ссылается
кейс соответствия, и id, текст которого есть только в этом репозитории, — ссылка в пустоту для
того, кто читает с другого языка.

```kotlin
val rules = KompotSpecResources(root = "kompot-spec").rules()
rules["9.4.3"] // "Ошибка, поднятая до того, как поле скрылось, перестаёт действовать вместе с полем."
```

## Совместимость изменений

Какие изменения схемы другая сторона переживает, решают правила §15: новый компонент деградирует до
заглушки, новое поле формы стоит старому клиенту всего ответа. `SchemaCompatibility` применяет их к
двум наборам документов, вместо того чтобы оставлять это глазу, читающему дифф сгенерированного
JSON, где оба случая выглядят одинаково. CI гоняет его на каждом pull request против ревизии, от
которой отрезана ветка; приложение, сверяющее свою схему со своей историей, зовёт ту же функцию.

```kotlin
SchemaCompatibility.compare(before, after).filter { it.verdict != Compatibility.COMPATIBLE }
```

## Проверка живого сервера

Вторая половина — [`kompot-tck`](../kompot-tck/README.md): он ходит в **работающий** сервер по
HTTP и проверяет то, что схеме не выразить, — уникальность id, согласие экрана и схемы формы,
ETag, пагинацию, 401, идемпотентность, изоляцию подписчиков канала.
