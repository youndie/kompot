# B-53 — refresh: перезагрузить текущий экран, не называя его

Самый частый ответ на `perform` — «покажи тот же экран заново». Сегодня это `navigate` на
собственный deeplink (§4.4), и у этого две цены: сервер обязан знать, с какого экрана пришло
действие (а для строки в общем списке это не всегда он), и клиент кладёт в стек навигации второй
экземпляр того же экрана, если приложение не догадалось сравнить.

- **Решение: действие `refresh`** без полей. Клиент перезапрашивает эндпоинт текущего экрана и
  применяет новое дерево по правилам §4.4 (состояние узлов под стабильными `id` переживает).
- Старый клиент: `UNKNOWN_ACTION`, экран не обновится. На переходный период сервер может отвечать
  `navigate` клиентам, объявившим старую версию, — записать в §15 как пример.

- AC: `perform` отвечает `refresh` → экран перезапрошен, стек навигации не вырос, позиция списка
  сохранена; SPEC §16.4.
- Якоря: `kompot-standard/.../Components.kt`, `kompot-navigation`, `kompot-spec/SPEC.md` §4.4, §16.4.
