# B-42 — Отказ подписки на обновления проглатывается молча

`KompotRealtimeProvider` ловит любое исключение подписки и не делает ничего:

```kotlin
} catch (e: Exception) {
    if (e is CancellationException) throw e
    // TODO: Log the exception
}
```

Экран при этом продолжает выглядеть живым: дерево на месте, обновлений просто больше нет. README
обещает «degrades rather than breaks», и первая половина выполнена — не падает; вторая, которую
[B-34](B-34-degradation-vocabulary-is-ambiguous.md) сделала словарём (`KompotDegradationSink`),
здесь не участвует: деградация есть, а сообщить о ней некуда.

- **Решение: отказ уходит в сток деградации отдельным видом** (`REALTIME_UNAVAILABLE` или близкое
  имя) с топиком и исключением. Сток уже есть, приложение его уже подключает, и второй канал
  ошибок рядом с ним был бы тем же, чем был boolean до B-34.
- Переподключение — отдельный вопрос, не этой задачи. Здесь — только чтобы отказ стал виден.
- Не делаем: не показываем пользователю ничего от имени тулкита. Что рисовать при потере канала,
  решает приложение, получив событие.

- AC: `source.subscribe` бросает → сток получает событие с топиком; тест в `kompot-client`
  держит это прогоном, а отмена корутины событием не считается.
- Якоря: `kompot-client/src/commonMain/kotlin/io/github/youndie/kompot/Realtime.kt:41`,
  `.../Degradation.kt`, README `kompot-client`.

## Находки

### Итерация 1 — 2026-09-24

**Не «отдельный вид», а отдельный член стока — и это отступление от решения выше.** Решение
писалось без взгляда на форму стока: `onUnknown(kind, originalType, outcome)` описывает дыру в
словаре провода, и его второй параметр — проводное имя типа. У отказа канала типа нет, а нужное
читающему — причина (401, обрыв) — это исключение, которому в `onUnknown` места нет. Четвёртое
значение `KompotDegradationKind` потеряло бы причину, заставило бы положить топик в поле для имени
типа и сломало бы каждый исчерпывающий `when` у потребителя. Поэтому — `onRealtimeFailure(topic,
cause)` в том же стоке, с реализацией по умолчанию (`println`, как у остального). Суть решения —
один канал деградации, а не второй рядом — сохранена; ломающего изменения нет (ABI-дифф — только
добавления: метод и `DefaultImpls`).

**Сток-лямбда остаётся лямбдой.** `fun interface` с членом по умолчанию по-прежнему SAM: сток,
написанный лямбдой, компилируется и получает отказ канала через `println`; чтобы маршрутизировать и
его, сток пишется объектом — это в README `kompot-client`.

**Контроли (мутации после коммита):**

| мутация | что сказал тест |
|---|---|
| вызов стока заменён на `sink.takeIf { topic.isEmpty() }?.onRealtimeFailure(…)` | «a channel that fails is reported…» — `expected: <1> but was: <0>` |
| отмена тоже уходит в сток | «leaving the screen… is not reported» — `expected: <[]> but was: <[Failure(… CancellationException …)]>` |

Первая попытка мутации (вызов заменён на `Unit`) была убита **компилятором** (`-Werror`: «Expression
is unused»), а не тестом, — такой мутант ничего не доказывает, поэтому заменён на компилирующийся.

**Второй тест держит обе стороны.** Он проверяет, что подписка была живой до ухода с экрана
(`subscribed`), — иначе «отказа не было» проходило бы и там, где подписки не было вовсе.

**Переподключение** — не здесь, как и решено выше; README `kompot-client` говорит, что его делает
приложение.
