# B-84 — Пришедшее заново равное дерево тоже сбрасывает подмены

Хранилище подмен (B-81) сбрасывается только деревом, **не равным** тому, что на экране:
`ProvideScreenOverrides` держит номер дерева под `remember(overrides, root)` («равное дерево — не
новость», `NodeOverrides.kt`). После B-82 это правило расходится с §16.4. `update` подменил узлы и
сменил адрес. Человек нажимает «назад», и приложение загружает экран прежнего адреса — **то же самое
дерево**, равное исходному, — но подмены остаются. На экране результаты фильтра, а в адресе —
страница без него. Нашёл открытый потребитель haul (у него это B-63; обход — новое хранилище на
каждый пришедший экран).

Воспроизведение (desktopTest):

```kotlin
val overrides = KompotNodeOverrides()
var tree by mutableStateOf<KompotComponent>(ColumnComponent("page", listOf(TextComponent("t", "before"))))
setContent { CompositionLocalProvider(LocalKompotNodeOverrides provides overrides) { KompotScreen(tree, …) } }
overrides.override("t", TextComponent("t", "after"))                  // что делает `update`
tree = ColumnComponent("page", listOf(TextComponent("t", "before")))  // «назад»: экран того адреса, равный
// рисуется «after», а экран адреса говорит «before»
```

- **Решение: дерево сбрасывает подмены, когда оно пришло, а не когда отличается.** «Пришло» — это
  событие доставки: загрузка завершилась (`KompotScreenLoader` знает каждую) или приложение отдало
  экрану новое дерево. Равенство значений остаётся только для перекомпозиции, при которой ничего не
  приходило.
- Состояние узлов под `id` (§4.4, §4.12) не трогается: сбрасываются подмены, а не выбор человека.
- Не делаем: ничего в проводе.

- AC: тест-воспроизведение выше красный на `main` и зелёный после; `refresh`, вернувший равное
  дерево, тоже сбрасывает подмены; перекомпозиция с тем же деревом подмен не сбрасывает; SPEC §4.4
  уточнён; мутации убиты.
- Якоря: `kompot-client/src/commonMain/kotlin/io/github/youndie/kompot/NodeOverrides.kt`,
  `ScreenLoader.kt`, `Components.kt`, `kompot-spec/SPEC.md` §4.4.

## Находки

### Итерация 1 — 2026-10-09

- **Дефект подтверждён до правки.** На неизменённом коде (база `a1a0882`) два теста-пробы красные на
  `onNodeWithText("before").assertExists()`, а контроль перед этим (`"after"` виден) зелёный: подмена
  легла, а пришедшее равное дерево её не сняло. Первый — воспроизведение из пункта буквально
  (`KompotScreen` и `tree = <равное дерево>`), второй — `KompotScreenLoader`, у которого новый ключ под
  тем же `screenKey` загрузил дерево, равное нарисованному. Лог — `/tmp/b84-before-fix.log` на WSL.
- **Буквальное воспроизведение зелёным не станет — и не должно.** `mutableStateOf` по умолчанию
  сравнивает значения: запись равного дерева в состояние — не запись, перекомпозиции нет вовсе, и
  экрану нечего отличать. Доставку знает только тот, кто её сделал, поэтому в зелёной версии
  приложение вместе с деревом меняет `arrival` (как в тексте пункта, где `KompotScreen(tree, …)`
  оставляет место для аргумента).
- **Устройство.** «Пришло» — событие, а не отличие:
  - `KompotScreenLoaderState` считает завершённые загрузки (`internal var arrivals`, растёт в том же
    кадре, что и `screen`), и загрузчик отдаёт номер вниз вокруг `content(tree)` через внутренний
    `LocalKompotTreeArrival`. Сигнатура загрузчика не менялась: номер едет локалью, а не параметром
    `content`, иначе сломался бы исходный код каждого потребителя;
  - `KompotScreen(…, arrival: Any? = null)` и `KompotLazyScreen(…, contentPadding, arrival: Any? = null)` —
    для экрана без загрузчика: значение, которое меняется с каждой доставкой (счётчик рядом с
    присвоением дерева). Прежние сигнатуры остались скрытыми перегрузками (`DeprecationLevel.HIDDEN`),
    в дампах они `synthetic` — бинарная совместимость сохранена, исходная тоже (параметр последний и
    с умолчанием);
  - `ProvideScreenOverrides` берёт номер дерева под `remember(overrides, root, arrival, delivered)`:
    доставка с любой стороны — новый номер, а без доставки решает равенство, как раньше.
  - Отвергнуто: ключевать экран номером доставки (`key(arrivals)` вокруг `content`) — снимает вместе
    с подменами и состояние под `id` (мутация 6 ниже это показала); считать доставкой начало загрузки —
    кадр канала пропадал бы, пока следующий ключ ещё едет (мутация 4).
- **`refresh` через загрузчик — это новый `key` под тем же `screenKey`** (счётчик в ключе): его
  завершённая загрузка и есть доставка. Отдельного «перезагрузить» у загрузчика нет и не понадобилось;
  записано в KDoc `withRefresh` и в README клиента.
- **Перекомпозицию с равным деревом держат двое.** Compose сравнивает дерево по значению и пропускает
  `ProvideScreenOverrides` целиком, если дерево равно, `arrival` тот же и локаль загрузчика не
  менялась, — трассировка на WSL показала, что тело не исполняется даже при новом `contentPadding`
  у `KompotLazyScreen`. Поэтому мутация «новый номер на каждое исполнение»
  (`remember(…, Any())`) **выжила**: она эквивалентна, пока работает пропуск, и через публичный API
  не наблюдается. Тест «a recomposition that hands the screen an equal tree keeps the overrides»
  остаётся как сторож поведения (новый экземпляр равного дерева, `neverEqualPolicy`, меняющийся
  `contentPadding`, контроль — счётчик перекомпозиций вызывающего).
- **SPEC §4.4** уточнён: «пришло» — доставка, а не отличие; равенство решает только при перерисовке;
  состояние под `id` (вкладка, секция, догруженные страницы) — не подмена и остаётся; абзац про
  «назад» после `update` и про то, откуда Kotlin-клиент знает о доставке. Фраза B-81 «равное дерево
  новым не считается» переписана там же, в KDoc `KompotNodeOverrides`, в README клиента и в записи
  0.40.0 `UPGRADING.md` (версия не выпущена). Новой записи в `UPGRADING.md` нет: коммит без `!`,
  `breaking_changes.py --base origin/main` — «объявленных ломающих нет».
- **Тесты** — `TreeArrivalTest` (7): воспроизведение с `arrival`; перекомпозиция с равным деревом;
  загрузка равного дерева под новым ключом; `refresh` через загрузчик и через `KompotLazyScreen` с
  `arrival`; кадр канала остаётся, пока загрузка едет, снимается пришедшим деревом, а кадр после
  доставки применяется; вкладка и раскрытая секция переживают доставку равного дерева.
- **Мутации** (по одной, исходник восстановлен копией, `git status` — только задуманные файлы):
  1. `arrival` выпал из ключей `remember` — красные оба теста с `arrival`;
  2. номер загрузки выпал из ключей — красные четыре теста загрузчика;
  3. загрузчик не считает загрузки — те же четыре;
  4. загрузчик считает при старте загрузки — красный «a live frame stays while a load is on its way…»;
  5. номер дерева без `remember` — красные оба теста с `arrival` и два `NodeOverridesTest`
     (параметры, которые тело не читает, Compose при пропуске не сравнивает, и экран перестал видеть
     доставку вовсе);
  5а. новый номер на каждое исполнение — выжила, см. выше;
  6. `key(arrivals)` вокруг `content` — красные «…leaves the state under ids alone» и
     `ScreenLoaderTest` «a new key keeps the drawn tree and its scroll…»;
  7. `KompotLazyScreen` не передаёт `arrival` — красный тест ленивого `refresh`;
  8. `KompotScreen` не передаёт `arrival` — красное воспроизведение.
