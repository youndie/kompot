# B-81 — Экран держит своё дерево: загрузчик без сброса, одно хранилище подмен, key(id)

Клиентская половина [research-partial-updates](../research/research-partial-updates.md) §4.1.
Провод не меняется.

- **`KompotScreenLoader` не сбрасывает нарисованное дерево**, пока едет следующее. Экран загрузки
  рисуется, только когда рисовать нечего: при первом показе или когда приложение сказало, что это
  другой экран. Неудачная загрузка оставляет прежнее дерево, слот ошибки получает причину и повтор.
  Приложение узнаёт, что загрузка в пути (для своего индикатора). Сигнатура остаётся совместимой
  по исходникам; поломка бинарной совместимости — запись в `UPGRADING.md`.
- **Одно хранилище переопределений узлов на экран.** В него пишут кадры канала, а после B-82 — и
  `update`. `RenderNode` по-прежнему единственная точка подмены. Правила жизни (§4.1 ресёрча):
  - новое дерево целиком сбрасывает переопределения;
  - переопределение `X` снимает переопределения внутри прежнего `X`;
  - незнакомый `id` игнорируется.

  `KompotRealtimeProvider` пишет в это хранилище, а не держит свою карту.
- **`key(id)` у детей нелинивых `column` и `row`.** Состояние `tabs`, `expandable` и списка
  держится за `id`, а не за позицию.
- SPEC: §4.4 дописывается правилом жизни переопределений; §12.6 — тем, что загрузчик держит
  прежнее дерево.

- AC:
  - тест: экран `A` → новый ключ, загрузка висит → на экране всё ещё дерево `A`, не экран
    загрузки; прокрутка сохранена;
  - тест: кадр канала подменил узел → `refresh` с новой версией узла → виден узел из нового
    дерева (сначала тест, подтверждающий нынешний дефект, на `main`);
  - тест: над раскрытым `expandable` в `column` вставлен узел → раскрыт тот же `expandable`;
  - мутации каждого из трёх убиты; `kompot-client-tck` без изменений зелёный.
- Якоря: `kompot-client/src/commonMain/kotlin/io/github/youndie/kompot/ScreenLoader.kt`,
  `Realtime.kt`, `Components.kt` (`RenderNode`, рендереры `column`/`row`), `kompot-spec/SPEC.md`
  §4.4, §12.6, `UPGRADING.md`.
