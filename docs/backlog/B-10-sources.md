# B-10 — Источники: файл, каталог с watch, HTTP с ETag + `NavigationGraph`

Цикл бэкенд-разработчика: правит DSL в IDE → сервер (или тест, пишущий фикстуру) отдаёт тело →
хочется увидеть его без перезапуска клиента. Тело у потребителя лежит в трёх местах: файл записи
(`/recorded/home-screen.json` в konekt), каталог таких записей, работающий сервер с
`NavigationGraph` (`routes: List<ScreenRoute(deeplink, endpoint, title, kind)>`) и ETag'ом
(`respondWithETag`: sha256 тела, 304 на `If-None-Match`).

- **Решение: `sealed interface ScreenSource`: `File(path)`, `Directory(path)`, `Http(baseUrl,
  headers, graphPath?)`.** Каталог — `WatchService` с `SensitivityWatchEventModifier.HIGH` (на
  macOS это polling; 2 с достаточно). HTTP — опрос по `If-None-Match`, перерисовка только на 200;
  список экранов слева — из `NavigationGraph`, загрузка по `endpoint`, тип тела по `kind`
  (`screen` / `form` / `live_screen`). Потому что все три уже существуют у потребителя как
  артефакты, и студия должна открывать их, а не просить новый формат.
- Bearer-токен для HTTP — из заголовков конфига источника; `kompot-auth`'овский
  `UpdateSessionAction` из лога действий можно «принять» кнопкой — этого в v1 нет, только заголовок.
- Альтернатива — только файл: цикл «сохранить ответ руками → открыть» убивает главное — скорость.
- Не делаем: live-канал (`KompotRealtimeSource`) — v2 при необходимости; запись тела в
  фикстуру — B-16.

- AC: открытие файла рисует его; правка файла на диске перерисовывает ≤ 3 с; при `Http` с
  `graphPath` слева список маршрутов, клик грузит экран; повторный опрос с неизменённым ETag не
  перерисовывает (видно по счётчику рендеров в статусной строке).
- Якоря: `kompot-studio/.../source/{ScreenSource,FileSource,DirectorySource,HttpSource}.kt`
  (новые), `kompot-navigation/.../NavigationGraph.kt`, `kompot-ktor/src/jvmMain/.../ETagResponses.kt`,
  `kompot-client-cache/.../KompotScreenFetcher.kt` (контракт, под который пишется HTTP).

## Итог

`ScreenSource.{File,Directory,Http}` + `open(scope)` → `ScreenSourceSession(screens, body(ref))`;
в конфиге поле `sources`, в окне — панель экранов слева и статусная строка. Три теста в
`ScreenSourceTest` зелёные, окно проверено запуском на каталоге записей
(`./gradlew :kompot-studio:run --args=<каталог>`).

- **WatchService не взят, и это решение, а не срез угла.** На macOS у него нет нативного бэкенда:
  `SensitivityWatchEventModifier.HIGH` — это «опрашивать раз в две секунды», то есть **медленнее**
  простого опроса, через `com.sun.nio.file`, помеченный к удалению с JDK 15. И это **разный механизм
  по платформам**: на Linux inotify срабатывает мгновенно, поэтому тест «правка файла доехала до
  окна» проходил бы в CI по причине, которой нет на машине, где студией пользуются. Один опрос
  раз в секунду — одинаковый везде и проверяемый один раз.
- **Два счётчика, а не один.** `checks` — сколько раз спросили, `revisions` — сколько раз ответ
  **отличался**. ETag существует ровно чтобы эти числа разошлись, и окно, показывающее только
  «перерисовалось», не отличает работающую ревалидацию от сервера, игнорирующего `If-None-Match`:
  оба рисуют одно и то же. В статусной строке — «polled N, changed M».
- **Тест ETag имеет положительный контроль.** Сервер считает свои 304, и тест требует, чтобы их было
  больше нуля: без этого источник, вообще не посылающий `If-None-Match`, прошёл бы все остальные
  утверждения. Файловый тест так же сначала даёт опросу поработать по неизменному файлу и требует,
  чтобы это не стоило ни одной ревизии, — иначе непроверенной осталась бы именно та половина.
- **`KompotScreenFetcher` не реализуется, хотя это первое, за чем тянется рука.** Контракт отдаёт
  **декодированный** `KompotComponent`, а источник правды студии — текст: тело, у корня которого
  пропал дискриминатор, обязано доехать до окна целиком. Заимствована форма условного запроса,
  а не тип возврата.
- **HTTP — `java.net.http`, а не Ktor-клиент,** хотя тулкит от него уже зависит: модуль публикуется,
  и каждая названная зависимость приезжает в POM инструмента, который потребитель добавляет себе.
  JDK-клиент умеет условный GET, а это и есть всё требование.
- **Граф читается один раз.** Он описывает, какие экраны у сборки есть, и меняется на деплое, а не
  пока на один из них смотрят; опрос графа тратил бы запрос в секунду ни на что.
- **Ошибка не стирает текст.** Файл в момент перезаписи нечитаем, и обнуление окна на каждое
  сохранение сделало бы студию непригодной ровно для того цикла, ради которого она есть.
