# B-52 — sequence: несколько действий одним ответом

Ответ на `perform`, сабмит и переход сценария — один `KompotAction` (§11.5, §16.4). «Обновить
сессию и перейти», «сообщить и закрыть», «скопировать и сообщить» одним ответом не выражаются;
сервер выбирает одно, остальное теряется.

- **Решение: действие `sequence`** со списком действий, выполняемых по порядку через ту же цепочку
  обработчиков. Остановка на первом неудачном — только если у обработчика есть понятие неудачи; если
  нет, записать, что `sequence` не транзакция.
- Незнакомое действие внутри — пропускается с событием деградации, остальные выполняются: одно
  непонятное слово не должно отменять понятные.
- Старый клиент не знает самого `sequence` → `UNKNOWN_ACTION`, не выполняется ничего. Это хуже, чем
  у одиночных новых действий, и в SPEC должно стоять рядом с правилом раскатки §15.

- AC: `sequence [update_session, navigate]` выполняет оба по порядку; незнакомое действие в середине
  даёт событие деградации и не останавливает хвост; фикстура корпуса случаев держит оба исхода.
- Якоря: `kompot-standard/.../Components.kt`, `kompot-client/.../ActionInterceptor.kt`,
  `kompot-spec/SPEC.md` §11.5, §16.4.
