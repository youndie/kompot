# B-38 — Проводное имя компонента получить нечем, а студия его требует

`KompotStudioConfig.samples` объявлен как `List<Pair<String, KompotComponent>>`: потребитель обязан
назвать **проводное** имя каждого образца строкой. Способа его получить у тулкита нет —
`KompotComponent.wireType()` в
[`kompot-client/.../Components.kt`](../../kompot-client/src/commonMain/kotlin/io/github/youndie/kompot/Components.kt)
`internal`, а публичного эквивалента не существует.

Нашлось это [B-37](B-37-readme-snippets-are-unchecked.md): README студии показывал
`samples = showcaseComponents().map { wireTypeOf(it) to it }`, и проверка имён сказала, что
`wireTypeOf` нет нигде. То есть строка в документации была написана под API, которого не завели, и
полтора года никто этого не заметил — потому что скопировать её и не собрать дешевле, чем
пожаловаться.

**Ошибка здесь молчит, и это главное.** `paletteFor` сверяет ключ образца с `discriminator.mapping`
профиля (`kompot-studio/.../palette/Palette.kt`): не совпало — `hasSample = false`, образец просто
не появляется. Ни сообщения, ни красного: палитра выглядит так же, как у потребителя, который
образцов не заводил вовсе.

- **Решение: не спрашивать имя, а выводить его.** `samples: List<KompotComponent>`, ключ считает сама
  студия тем же путём, что и клиент. Это убирает класс ошибки целиком, а не даёт инструмент писать
  строку правильно. Цена — ломающее изменение `KompotStudioConfig`, и оно уместно: конфиг студии
  меняют один раз при подключении.
- **Альтернатива: публичный `wireTypeOf(component)`.** Ровно то, что обещал README, и на один шаг
  хуже: пара остаётся парой, и потребитель по-прежнему может написать в ней что угодно. Плюс
  публикует наружу `@OptIn(InternalSerializationApi::class)` — `wireType()` считает имя через
  `serializerOrNull()`, и цена этого опт-ина сейчас заперта внутри одного модуля.
- **Сторож нужен при любом выборе:** ключ образца, которого нет в `discriminator.mapping` профиля, —
  это опечатка, и студия обязана сказать об этом вслух. Сегодня она молчит, и при выведении ключа
  молчать станет не о чем только для образцов, чей тип есть в профиле; образец типа, которого в
  профиле нет, — всё ещё тихая дыра.
- Не делаем: не трогаем `wireType()` внутри клиента и его поведение для лога деградации — там он
  работает и покрыт (B-34).

- AC: потребитель заводит образцы, не написав ни одного проводного имени руками; образец, тип
  которого профиль не знает, роняет открытие студии с сообщением, называющим тип; README студии
  показывает то, что собирается (проверка B-37 это подтверждает).
- Якоря: `kompot-studio/src/desktopMain/kotlin/io/github/youndie/kompot/studio/KompotStudioConfig.kt`,
  `kompot-studio/src/desktopMain/kotlin/io/github/youndie/kompot/studio/palette/Palette.kt`,
  `kompot-client/src/commonMain/kotlin/io/github/youndie/kompot/Components.kt`,
  `kompot-studio/README.md`.

## Находки

### Итерация 1 — 2026-09-19

**Имя выводится энкодером, а не поиском сериализатора — и это оказалось не «как получится», а
лучше.** Первый план был опубликовать `wireType()` из клиента. Не понадобилось: у студии уже есть
`config.json`, и `Json.encodeKompotComponent` пишет дискриминатор — значит имя можно прочитать из
закодированного тела. Это буквально та строка, которую напишет сервер, а не ответ про класс. Плюс
`@OptIn(InternalSerializationApi::class)` остался запертым в одном модуле, как и было.

Побочно выяснилось, что у этого пути есть свой сторож даром: образец типа, которого нет в модуле
сериализаторов, не кодируется вовсе. Раньше такой образец молча жил в конфиге под именем, которое
потребитель написал руками; теперь он падает с именем класса и подсказкой.

**Проверка образцов стоит до открытия окна.** `checkSamples(config)` вызывается в `kompotStudio()`
перед `application { }`: все три жалобы — про конфигурацию, а не про тело, и каждая раньше
заканчивалась панелью, которая тихо показывала меньше.

**Три мутации прогнаны, каждая красная:**

| мутация | упавший тест |
|---|---|
| снят `require` на дубликат | `two samples of one type are named, rather than one winning` |
| снят `require` в `checkSamples` | `a sample of a type no schema declares stops the studio, naming the type` |
| падение кодирования возвращает имя класса | `a sample the Json cannot encode is named, not skipped` |

Отрицательный контроль на месте: конфиг без схем `checkSamples` проходит — закрытого списка нет, и
сторож, срабатывающий здесь, сделал бы ненастроенную студию не слепой, а неработающей.

**Сломано публичное API.** `KompotStudioConfig.samples` сменил тип; `kompot-studio` публикуется, так
что это `BREAKING CHANGE` в сообщении коммита. Меняется он один раз при подключении студии, и
альтернатива — оставить пару и дать `wireTypeOf` — оставляла бы возможность написать в ней что
угодно.

**Документ исправлен вместе с кодом:** `docs/research/research-studio.md` показывал старую подпись
`KompotStudioConfig`.
