# B-57 — TypeScript-типы из schema/*.json для клиента не на Kotlin

Самые полезные находки у kompot приходили не из своего сьюта, а от реализаций на другой стороне
провода: сервер на Go, клиент на React. Схемы для них уже есть (`kompot-spec/schema/*.json`,
генерируются, проверяются на совместимость), но читающая сторона на TypeScript пишет типы руками —
то есть заново переписывает то, что схема уже сказала, и расходится с ней молча.

- **Решение: генерировать `.d.ts` из схем** в `kompot-spec` той же задачей, что пишет схемы, и
  класть рядом — с проверкой «сгенерированное совпадает с закоммиченным», как у голденов схем.
  Дискриминированные объединения по `type` — прямо из `x-kompot-contributes`.
- Открытые иерархии (§2.1) в TS выражаются объединением известных вариантов **плюс** ветка
  неизвестного `{ type: string }` — иначе типы обещают закрытость, которой у протокола нет.
- Публиковать ли npm-пакет — не в этой задаче; сначала файлы в репозитории и один потребитель.
- Не делаем: рендерер на React. Это следующая ступень, и её лучше делать потребителю, а не нам.

- AC: `.d.ts` для всех схем в репозитории; проверка в `check` краснеет, если схема изменилась, а
  типы нет; тело из корпуса эталонных тел проходит `tsc` против этих типов.
- Якоря: `kompot-spec/`, `kompot-spec/schema/`, `.github/workflows/build.yaml`.
