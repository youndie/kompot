# B-15 — Редактор текста с подсветкой JSON и синхронизацией каретка ↔ узел

Источник правды — текст тела (research §5.3), а в v1 он только читается. Зрелого редактора кода
для Compose Desktop нет: Qawaz/compose-code-editor заброшен (2024), Jewel даёт `TextArea` без
подсветки, Monaco недоступен без WebView. Тела экранов — единицы-десятки КБ, так что задача
не в производительности, а в трёх вещах: подсветка, позиция ошибки, связь с деревом.

- **Решение: `BasicTextField(TextFieldState)` + `OutputTransformation` с собственным JSON-лексером
  (строки, числа, ключи, `type`-ключ и его значение — отдельным стилем) в `AnnotatedString`;
  ошибки синтаксиса подчёркиваются по offset'у из `SerializationException`; каретка → узел через
  карту `JsonPath → TextRange`, построенную одним проходом лексера.** Потому что новый API
  `TextFieldState` даёт стабильный offset-mapping (легаси `VisualTransformation` известен
  ошибками смещений), а карта диапазонов нужна и дереву (B-11: выбор узла → каретка), и
  диагностике (B-12: запись → строка).
- Перерисовка — по debounce 150 мс после успешного парса; при ошибке синтаксиса кадр остаётся
  прежним, а запись слоя 1 показывает где.
- Альтернатива — Highlights (KMP-движок подсветки): умеет JSON, но не даёт карту путей; лексер
  на 150 строк дешевле, чем зависимость плюс второй проход.
- Не делаем: автодополнение по схеме — v3 вместе с инспектором; форматирование —
  одна кнопка `Json { prettyPrint }`.

- AC: набор текста подсвечивается без заметной задержки на теле 100 КБ; клик по узлу в дереве
  ставит каретку на его `"type"`; клик по записи диагностики — тоже; удаление запятой даёт
  подчёркивание и запись слоя 1, кадр не пропадает.
- Якоря: `kompot-studio/.../editor/{BodyEditor,JsonLexer,PathRanges}.kt` (новые), B-11 `TreeModel`.

## Итог

`editor/JsonLexer.kt` (токены + карта `путь → диапазон` одним проходом) и `editor/BodyEditor.kt`
(`BasicTextField(TextFieldState)` + `OutputTransformation` со `SpanStyle`, две палитры). В окне:
подсветка, подчёркивание места отказа парсера, каретка на узле по клику в дереве **и** по клику в
диагностике, дебаунс 150 мс. Шесть тестов в `JsonLexerTest`; окно проверено запуском.

- **`TextFieldBuffer.addStyle` существует в этой линии Compose** — это проверено по байткоду
  `foundation-desktop-1.11.1`, а не предположено: новый `BasicTextField(TextFieldState)` долго не умел
  стилизовать вывод, и если бы не умел здесь, вся задача поехала бы на легаси `VisualTransformation`
  с его известными ошибками смещений.
- **Один проход даёт оба ответа.** Подсветка и карта путей — это одна и та же прогулка по тексту;
  вторая прогулка — это способ, которым они расходятся, и расхождение выглядит как каретка, иногда
  прыгающая не туда. Карта путей вообще недостижима другим путём: kotlinx-serialization разбирает в
  дерево **без смещений**, поэтому ничто, что декодирует тело, не может сказать, где узел написан.
- **Сшивка проверена тестом.** `screenTree(...).flatten().map { path }` — каждый путь обязан быть
  ключом в `lexJson(body).nodes`. Это единственное место, где сходятся два независимых обхода, и его
  отказ выглядел бы как «иногда не работает».
- **Лексер не бросает и не сдаётся рано** — недопечатанное тело это норма, а не край. Шесть таких
  входов в тесте (оборванная строка, пропущенная запятая, одна скобка, пустая строка, экранированная
  кавычка), плюс инвариант «токены не пересекаются и лежат внутри текста»: диапазон за концом валит
  текстовое поле, а пересекающийся красит токен цветом соседа.
- **Кадр рисуется из последнего РАЗОБРАВШЕГОСЯ текста и только после паузы.** Две отдельные причины,
  обе про то, что полунабранное состояние — обычное: перерисовка на каждое нажатие рисует экран,
  который ещё не дописан, а тело, которое не разбирается, нарисовать нельзя вовсе — и гасить кадр,
  пока кто-то стирает запятую, значило бы ломать студию ровно там, где она нужна.
- **Каретка ставится на слово, называющее узел** (`"column"`), а не на скобку; у объекта без `type` —
  на открывающую скобку, потому что больше не на что.
- Подсветка своя, а не Highlights: движок раскрасил бы JSON и ничего не знает о путях — это была бы
  зависимость плюс второй проход ради половины, которую он не делает.
