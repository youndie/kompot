# B-45 — box: наложение узлов друг на друга

В словаре три контейнера — `row`, `column`, `table` — и все раскладывают детей рядом. Положить
один узел **поверх** другого нечем: бейдж на картинке, подпись на баннере, счётчик в углу аватара,
градиент-затемнение под текстом. Каждое из этого сегодня — повод завести продуктовый тип провода,
то есть свойство раскладки переезжает в словарь (ровно то, против чего написан §5.5).

- **Решение: новый тип `box`** — дети в порядке z, у каждого выравнивание внутри коробки. Тип, а не
  поле у `column`, потому что меняется смысл `children`, а не оформление.
- **Нужен `fallback` (§2.1).** Старый клиент `box` не знает. Серверу — рекомендация в SPEC: в
  фолбэке `column` с теми же детьми, то есть «бейдж под картинкой» вместо дыры.
- Выравнивание ребёнка в коробке — тот же набор слов, что `alignment` из
  [B-44](B-44-row-and-column-alignment.md), только по двум осям (`top_start` … `bottom_end`). Потому и
  `blocked_by`: словарь выравнивания заводится один раз.
- Не делаем: абсолютные координаты (`offset` в dp). Сервер не знает окна; смещение, заданное
  числом, разъезжается на первом узком экране.

- AC: `box` с картинкой и текстом в `bottom_start` рисуется наложением в Compose и в браузере;
  плейграунд показывает три состояния деградации для `box` (незнакомый тип, заглушка, серверный
  фолбэк); профиль и схема знают тип.
- Якоря: `kompot-standard/.../Components.kt`, `kompot-client/.../Components.kt`,
  `kompot-spec/SPEC.md` §2.1, §4, `kompot-playground/`.
