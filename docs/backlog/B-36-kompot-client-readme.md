# B-36 — У kompot-client нет README

`kompot-client` — самая большая поверхность читающей стороны: реестр рендереров, `kompotJson`,
деградация и её сток, декоратор реестра. Файла README у модуля нет вовсе, поэтому всё, что про него
написано, написано либо в KDoc (виден тому, кто уже подключил артефакт), либо в корневом README
(где у этого нет места — он про тулкит целиком).

Двое подряд в это упёрлись: [B-30](B-30-playground-examples-and-links.md) не смогла положить ссылку на
витрину «ближе к коду», а [B-31](B-31-question-placeholder-for-unknown.md) выпустила
`kompotVisiblePlaceholderRenderers` — опцию, про которую потребитель узнает, только если сам полезет
в исходники.

- **Решение: README у модуля, отвечающий на вопросы, которых нет больше нигде.** Как собрать реестр и
  что значит «плагин»; как маршрутизировать деградацию в своё логирование и что означают три исхода;
  как включить видимые заглушки в debug-сборке; ссылка на живую витрину.
- **Не пересказывать SPEC.md.** Правила протокола — там, и README, повторяющий их, расходится с ними в
  первый же месяц. Здесь — только то, что знает этот модуль: как его подключить и какие у него швы.
- **Ссылка на витрину отсюда, а не из корня.** Человек, пришедший за клиентом, попадает на README
  модуля; корневой README видит тот, кто ещё выбирает тулкит.
- Альтернатива — дописать всё в корневой README: он и так растёт, а раздел про клиента в нём должен
  оставаться одним абзацем.
- Не делаем: README остальным модулям. Здесь он нужен, потому что у модуля есть швы, которые
  потребитель обязан знать; у `kompot-core` таких нет.

- AC: потребитель, открывший `kompot-client` на GitHub, собирает реестр, направляет деградацию в своё
  логирование и включает видимые заглушки, не открывая SPEC.md; раздел про клиента в корневом README
  не начинает это повторять.
- Якоря: `kompot-client/README.md` (новый), `kompot-client/src/commonMain/kotlin/io/github/youndie/kompot/{Components,Degradation,KompotClient}.kt`,
  `README.md` (раздел про клиента).
