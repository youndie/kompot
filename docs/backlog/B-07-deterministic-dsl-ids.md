# B-07 — DSL: детерминированный id вместо `Uuid.random()`

`kompotScreen { column { text("…") } }` в `kompot-standard/.../Dsl.kt` подставляет
`id ?: Uuid.random().toString()` в шести местах. Два вызова одного и того же DSL дают два разных
дерева; диф по id (`tools/canvas/canvas_tree.py --compare`, записи стенда, будущий диф студии
«что изменилось») видит переименование каждого узла вместо правки одного. Live-обновление по id
(`LocalKompotRealtimeUpdates`) с таким id не адресуется вовсе.

- **Решение: id по умолчанию — путь узла в дереве** (`root`, `root/0`, `root/0/2`), выданный
  билдером при `build()`, когда родитель знает позицию ребёнка. Потому что уникальность в
  пределах дерева — единственное требование SPEC (§ про ids, проверяется TCK `component-id`), а
  путь уникален и стабилен между двумя сборками одного экрана.
- Явный id по-прежнему побеждает; сервер, которому нужен адресуемый узел, называет его сам —
  это не меняется.
- Альтернатива — хеш содержимого: стабилен, пока не меняется текст, и меняется ровно тогда, когда
  правка должна читаться как правка узла, а не его замена.
- Не делаем: не трогаем `UnknownComponent(id = "unknown")` и не требуем id от пользователей DSL.

- AC: два вызова `kompotScreen { … }` с одним телом дают равные деревья; `FormStandardDslTest`
  и тесты DSL зелёные; `kompot-tck` `component-id` на дереве из DSL без явных id проходит.
- Якоря: `kompot-standard/src/commonMain/kotlin/io/github/youndie/kompot/standard/Dsl.kt`,
  `kompot-core/src/commonMain/.../dsl/`, `kompot-forms-standard` (DSL форм).

## Итог

`KompotContainerContext.nextChildPath()` в `kompot-core`; оба DSL — стандартный и формовый — называют
безымянный узел его путём (`root`, `root/0`, `root/1/1/0`). Восемь `Uuid.random()` ушли. Тесты:
три в `DslTest`, один в `BodyRulesTest`; все затронутые наборы зелёные (в том числе скриншотные
голдены `kompot-ds-material-compose` — id поменялись, пиксели нет); три аудита публикации зелёные.

- **Тест утверждал ровно обратное, и его пришлось переписать.** `column without an explicit id
  generates a random one — different each time` фиксировал поведение, которое задача снимает. Новый
  тест называет причину: случайный id выполнял единственное правило (уникальность в дереве) и тихо
  ломал три вещи — диф по id читал правку одного слова как замену каждого узла, перезаписанная
  фикстура расходилась сама с собой, а live-обновление, адресующее узел **по id**, не адресовало
  ничего.
- **Путь наследует явное имя:** узел с `id = "card"` даёт детям `card/0`, а не `root/1/0`. Иначе
  вставка соседа выше сдвигала бы id всего названного поддерева — а это половина смысла его называть.
- **Шов — метод интерфейса с дефолтом**, а не смена сигнатуры `addComponent`: `KompotContainerContext`
  опубликован, и контейнер, написанный потребителем, продолжает работать по-старому (дефолт —
  прежний `Uuid.random()`), потому что реализация, не знающая своего места в дереве, не может выдать
  путь, а выдуманный — столкнётся.
- **Проверено правилом, а не только равенством деревьев:** отдельный тест кодирует дерево из DSL без
  единого явного id и требует, чтобы `BodyRules.componentIds` не нашёл ничего. Счётчик, сбрасываемый
  на каждом контейнере, или путь, забывший глубину, столкнулись бы именно там — дерево нарочно
  содержит два одинаковых по форме поддерева.
