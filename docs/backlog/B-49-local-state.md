# B-49 — Локальное состояние экрана: `tabs` и `expandable`

Выбрана ступень 0 из [research-local-state.md](../research/research-local-state.md) (ответ владельца
на [B-48](B-48-local-state-research.md), 2026-09-25): **компоненты со своим состоянием**, а не
состояние, разлитое по экрану. Вкладки и раскрываемая секция переключаются на клиенте, без запроса к
серверу; зависимость между узлами вне формы в эту задачу не входит (это ступень 1, её берут, когда
появится экран, который иначе не выражается).

- **Два типа в `kompot-standard`:** `tabs` (`tabs: [{ title, content }]`, `selected: Int = 0`) и
  `expandable` (`header`, `content`, `expanded: Boolean = false`). Типы, а не поля и не модификаторы:
  так старый клиент деградирует через `fallback`, который назвал сервер (§2.1), — единственный
  способ сказать ему «без состояния покажи вот так».
- **Жизнь состояния** (§4 research-документа, записать в SPEC рядом с §4.4): состояние под `id`;
  значение с провода — начальное и применяется заново, только если сервер прислал **другое**
  значение, чем в прошлый раз; иначе переживает `navigate` на тот же экран, `refresh`, кадр канала;
  кадр, заменивший узел другим типом, состояние сбрасывает.
- **Доступность:** вкладка — `Role.Tab` с выбранностью, заголовок раскрываемой секции — кнопка со
  состоянием «развёрнуто/свёрнуто» (как §4.11).
- Не делаем: `hidden`/`toggle`, переменные экрана, условия вне формы, анимации сверх того, что даёт
  Compose по умолчанию.

- AC:
  - экран с вкладками и раскрываемой секцией переключается без запроса к серверу — в Compose (тест)
    и в браузере (пример в плейграунде);
  - заново присланный узел с тем же `selected`/`expanded` не сбрасывает выбор человека, с другим —
    применяет новое (тест на каждый случай);
  - клиент 0.37 то же тело показывает через `fallback`; что именно он показывает — записано в SPEC и
    держится фикстурой корпуса случаев (`kompot-client-tck`) и `DegradationStatesTest` плейграунда;
  - `checkSchemaCompatibility` — `COMPATIBLE`; TypeScript-типы и голдены схемы перезаписаны;
  - SPEC: §4 — оба узла, правило жизни состояния.
- Якоря: `kompot-standard`, `kompot-client` (`Stack.kt`, `Layers.kt` — рядом с раскладкой),
  `kompot-spec/SPEC.md` §2.1, §4.4, §4.11, `kompot-client-tck`, `kompot-playground/.../Examples.kt`.

## Находки

- **Сделано:** `tabs` и `expandable` в `kompot-standard` (модель, DSL `tabs { tab(...) }` и
  `expandable(header, content)`), рендереры в `kompot-client` (`Disclosure.kt`), SPEC §4.12, пример
  «Tabs and sections that open, on the client» в плейграунде. `checkSchemaCompatibility` —
  `COMPATIBLE` (два новых типа в деградирующей иерархии и `TabsItem`); TypeScript-типы, голдены
  схемы и дампы ABI перезаписаны.
- **Правило жизни состояния реализовано одним местом** — `rememberSeeded`: состояние под `id`,
  значение с провода применяется при появлении и заново только при **другом** значении (эффект по
  ключу значения). Отдельно проверены: тот же `selected` целым деревом и кадром канала не сбрасывает
  выбор; другой — применяется; номер вне списка — первая вкладка.
- **Нажатие ничего не поднимает:** тесты держат, что обработчик действий пуст после переключения.
- **Доступность — на десктопе верная, в браузере — нет, и это Compose/Wasm.** Семантика узла:
  вкладка — `Role.Tab` с `selected` (даёт Material `Tab`), заголовок секции — `Role.Button` с
  действием `expand` или `collapse`; тест держит обе. Но зеркальный DOM Compose/Wasm (CMP 1.12.1)
  отдаёт вкладку как `role=button` без `aria-selected`, а заголовок — без `aria-expanded`; дерево
  доступности Chrome это подтверждает. В kompot исправлять нечего; issue в Compose Multiplatform —
  только спросив владельца (репозиторий чужой).
- **Корпус случаев не расширен.** `kompot-client-tck` описывает только поведение форм
  (`FormController`), формата для узлов интерфейса там нет; строить его ради двух узлов — отдельная
  задача. Что делает клиент 0.37, держит `DegradationStatesTest` плейграунда: для `expandable` —
  все три состояния, для `tabs` — `fallback`, названный в теле примера (все панели подряд, как
  рекомендует §4.12).
- **Мелкое по пути:** пояснение режима «старый клиент» в плейграунде говорило «на месте узла ничего
  не рисуется» — неверно для тела с `fallback`; уточнено.
- **Проверено:** `DisclosureTest` — 8 тестов; пять мутантов (сброс на каждой композиции, значение
  не применяется заново, номер вне списка — последняя, `expand`/`collapse` перепутаны, заголовок
  только открывает) — каждый роняет названные тесты. Плейграунд: 17 браузерных тестов; на странице
  вкладка и секция переключаются, журнал пуст, старый клиент рисует панели подряд. Полный
  `./gradlew build` с браузерными тестами на Linux-машине: 1266 тестов, 0 упавших.
