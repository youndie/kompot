# B-49 — Локальное состояние экрана: `tabs` и `expandable`

Выбрана ступень 0 из [research-local-state.md](../research/research-local-state.md) (ответ владельца
на [B-48](B-48-local-state-research.md), 2026-09-25): **компоненты со своим состоянием**, а не
состояние, разлитое по экрану. Вкладки и раскрываемая секция переключаются на клиенте, без запроса к
серверу; зависимость между узлами вне формы в эту задачу не входит (это ступень 1, её берут, когда
появится экран, который иначе не выражается).

- **Два типа в `kompot-standard`:** `tabs` (`tabs: [{ title, content }]`, `selected: Int = 0`) и
  `expandable` (`header`, `content`, `expanded: Boolean = false`). Типы, а не поля и не модификаторы:
  так старый клиент деградирует через `fallback`, который назвал сервер (§2.1), — единственный
  способ сказать ему «без состояния покажи вот так».
- **Жизнь состояния** (§4 research-документа, записать в SPEC рядом с §4.4): состояние под `id`;
  значение с провода — начальное и применяется заново, только если сервер прислал **другое**
  значение, чем в прошлый раз; иначе переживает `navigate` на тот же экран, `refresh`, кадр канала;
  кадр, заменивший узел другим типом, состояние сбрасывает.
- **Доступность:** вкладка — `Role.Tab` с выбранностью, заголовок раскрываемой секции — кнопка со
  состоянием «развёрнуто/свёрнуто» (как §4.11).
- Не делаем: `hidden`/`toggle`, переменные экрана, условия вне формы, анимации сверх того, что даёт
  Compose по умолчанию.

- AC:
  - экран с вкладками и раскрываемой секцией переключается без запроса к серверу — в Compose (тест)
    и в браузере (пример в плейграунде);
  - заново присланный узел с тем же `selected`/`expanded` не сбрасывает выбор человека, с другим —
    применяет новое (тест на каждый случай);
  - клиент 0.37 то же тело показывает через `fallback`; что именно он показывает — записано в SPEC и
    держится фикстурой корпуса случаев (`kompot-client-tck`) и `DegradationStatesTest` плейграунда;
  - `checkSchemaCompatibility` — `COMPATIBLE`; TypeScript-типы и голдены схемы перезаписаны;
  - SPEC: §4 — оба узла, правило жизни состояния.
- Якоря: `kompot-standard`, `kompot-client` (`Stack.kt`, `Layers.kt` — рядом с раскладкой),
  `kompot-spec/SPEC.md` §2.1, §4.4, §4.11, `kompot-client-tck`, `kompot-playground/.../Examples.kt`.
