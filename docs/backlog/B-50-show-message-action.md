# B-50 — show_message: короткое сообщение в ответ на действие

`perform` (§16.4) отвечает `KompotAction`, и на практике это `navigate` — перерисовать экран.
Сказать «скопировано», «сохранено», «не удалось, попробуйте позже» без перехода сервер не может:
`copy_text` копирует молча, успешный `perform` виден только по изменившемуся экрану, а 422 — это
тело `{"error": …}`, которое по §16.8 вообще не часть протокола.

- **Решение: действие `show_message`** — текст, необязательный уровень (`info`/`error`) и
  необязательное действие на кнопке сообщения («Отменить»). Действие, а не компонент: сообщение не
  живёт в дереве и не имеет `id`.
- Рисует приложение через дизайн-систему (snackbar, toast, баннер) — как и остальной хром, форма
  элемента не провод (§6).
- Старый клиент: `UNKNOWN_ACTION`, сообщение не показано, экран не сломан. Приемлемо — сообщение
  по определению не несёт того, без чего экран непонятен.
- Связка с [B-52](B-52-sequence-action.md): «сохранить → сообщить → закрыть» без неё не выражается
  одним ответом.

- AC: `perform` отвечает `show_message` → сообщение видно в Compose и в браузере; действие на
  кнопке сообщения уходит в обработчик; схема, профиль, SPEC §16.4.
- Якоря: `kompot-standard/.../Components.kt`, `kompot-client/.../Perform.kt`,
  `kompot-ds-material-compose/`, `kompot-spec/SPEC.md` §16.4, §16.8.

## Находки

### Итерация 1 — 2026-09-25

**Тулкит не выполняет стандартные действия сам** — `navigate`, `open_url`, `copy_text`, `close` уходят в
обработчик приложения. `show_message` — такое же действие; но чтобы «сообщение видно» было
проверяемо, у Material-дизайн-системы есть готовый показ: `withSnackbarMessages` в
`kompot-ds-material-compose`, та же форма, что `withPerform`. SPEC §16.4 — правило; совместимость
схемы — `type-added-degrading`.

**Первая версия отправляла кнопку сообщения не туда, и тест этого не видел.** Действие кнопки уходило
в обработчик, который помощник оборачивает, — мимо всего, что снаружи. В документированной цепочке
(`withSnackbarMessages` внутри `withPerform`) «Отменить», которое само `perform`, не отправилось бы
вовсе. Тест проверял кнопку на `navigate`, которое доходит до приложения и так. **Нашёл браузер**: в
плейграунде «Undo», поднимающее второе сообщение, не рисовало ничего. Исправлено параметром
`followUp` (вершина цепочки); добавлен тест, где кнопка поднимает `perform`, а сервер отвечает
сообщением; мутация «кнопка — во внутренний обработчик» убита именно им.

**Плейграунд показывает `show_message`** — пример «An answer in words», и `KompotPreview` на странице
получает обработчик с сообщениями: единственное действие, на которое странице без сервера есть что
ответить.

**Проверки:** 6 тестов (`MessagesTest`); мутации — кнопка не передаёт действие, подпись без действия,
кнопка во внутренний обработчик — все убиты своими тестами. Браузер: сообщение, кнопка «Undo»,
второе сообщение, консоль без ошибок.
