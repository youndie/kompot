# B-54 — Показ считается по композиции, а не по видимости

`withImpressionTracking` оборачивает каждый рендерер и шлёт `ComponentImpression` из
`LaunchedEffect(component.id)` — то есть когда узел **вошёл в композицию**. В ленивом списке это
близко к видимости. В обычном `column` — нет: карточка в самом низу длинного экрана «показана» в
момент открытия, даже если до неё никто не долистал. Для A/B-сравнения блоков, ради которого сервер
и держит экран, это систематически завышает показы всего, что ниже первого экрана.

Второе: отслеживается **каждый** узел. Сервер не может сказать «вот этот баннер — единица
измерения, остальное — раскладка».

- **Решение: видимость по доле площади в окне** (порог и время — параметры
  `withImpressionTracking`, не провода) и необязательное поле узла, которым сервер помечает
  отслеживаемое. Поле — по §3, старый клиент его игнорирует и считает как раньше.
- Не делаем: отправку событий. Тулкит отдаёт событие `AnalyticsTracker`, дальше — приложение.

- AC: карточка ниже окна не даёт события до прокрутки к ней (тест с измеряемой геометрией, не
  предположение); помеченный узел отслеживается, непомеченный — нет, когда пометки включены.
- Якоря: `kompot-client/src/commonMain/kotlin/io/github/youndie/kompot/ImpressionTracking.kt`,
  `kompot-analytics/.../AnalyticsEvent.kt`, `kompot-client/src/desktopTest/.../ImpressionTrackingTest.kt`.

## Находки

- **Сделано:** `withImpressionTracking(tracker, naming, ImpressionVisibility(...))` — доля площади в
  окне (`0.5` по умолчанию), минимальное время на экране (`0` по умолчанию) и предикат `track`.
  Старая сигнатура осталась и теперь считает по видимости: это смена поведения без смены API,
  поэтому объявлена ломающей и записана в `UPGRADING.md`.
- **Порог мерится по осям, с потолком в окно.** Первый вариант — «половина площади узла в окне» —
  никогда не считал корень длинного экрана: колонка в 1100 dp в окне 300 dp видна максимум на 27 %.
  «Половина площади окна» тоже неверна: узлы по ширине содержимого узкие (в тесте 32 px), и их
  площадь несравнима с площадью окна. По каждой оси видимая длина делится на меньшее из длины узла и
  длины окна; доли перемножаются.
- **Второй критерий выполнен наполовину.** Выбор узлов есть, но на стороне клиента (`track`).
  Серверную пометку сделать полем нельзя без поля у каждого типа компонента — модификаторы закрыты
  (§2.3), у `KompotComponent` только `id` и `modifiers`. Решение уровня протокола вынесено вопросом
  в [B-62](B-62-server-marks-the-measured-node.md); до его ответа сервер может помечать через `id`.
- **Проверено:** `ImpressionVisibilityTest` — карточка ниже окна не считается до прокрутки
  (геометрия меряется, окно 300×300); полсекунды на экране при пороге в секунду не считаются, полторы
  — считаются; узел выше окна считается, заполнив окно. Старый `ImpressionTrackingTest` зелёный без
  правок. Четыре мутанта (всегда видим, без потолка в окно, без задержки, без предиката) — каждый
  роняет хотя бы один тест.
