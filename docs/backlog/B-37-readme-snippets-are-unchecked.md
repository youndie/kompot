# B-37 — Kotlin-сниппеты в README ничем не компилируются

Корневой `README.md` и новый [`kompot-client/README.md`](../../kompot-client/README.md) показывают
сборку реестра, свой сток деградации и свой рендерер живым кодом — и ни один из этих блоков не
компилируется ничем. В CI над документацией гоняется ровно один скрипт,
`docs/scripts/backlog_index.py`, и он про бэклог.

Это не гипотеза о будущем: `drawnAsFallback` уже переименовывался (B-34), `UnknownComponentRenderer`
получал параметр (B-31), а `kompotJson` — аргумент вместо константы. Каждое такое переименование
оставляет в README код, который выглядит рабочим и не собирается, и узнаёт об этом первым не автор,
а тот, кто скопировал блок к себе.

- **Решение: компилировать блоки, а не сверять их глазами.** Достаточно теста в
  `kompot-client/src/desktopTest`, который вытаскивает ```` ```kotlin ````-блоки из README и
  сравнивает набор упомянутых в них публичных имён с тем, что модуль действительно экспортирует, —
  либо, если это окажется дешевле, положить сами блоки в исходник и включать их в README генератором.
  Второй вариант честнее: он компилируется целиком, а не по именам.
- Альтернатива — «следить руками при рефакторинге». Именно она сейчас и действует, и B-36 проверила
  идентификаторы грепом ровно один раз; следующее переименование об этой проверке не узнает.
- Не делаем: проверку прозы. Речь только про `kotlin`-блоки.

- AC: переименование публичного имени, использованного в README, роняет ~~сборку~~ **прогон CI**
  (см. находки: компилировать блоки нечем, и проверка встала рядом с `backlog_index.py`, а не в
  Gradle); прогон на текущем `main` зелёный, а на диффе с любым из блоков, испорченным вручную, —
  красный.
- Якоря: `README.md`, `kompot-client/README.md`, `kompot-client/src/desktopTest/`,
  `.github/workflows/build.yaml`.

## Находки

### Итерация 1 — 2026-09-19

**Компилировать блоки нечем, и это не лень.** Задача предлагала два варианта и называла честным
второй — «положить блоки в исходник». Он не собирается: 22 блока ссылаются на классы из модулей,
которые не лежат на одном класспасе (`kompot-client` — Compose, `kompot-spec` и `kompot-tck` —
JVM-инструменты, `kompot-ktor` — сервер), а четыре блока — Gradle DSL и куски с многоточием,
которые не компилируются в принципе. Собрать ради этого модуль, зависящий от всего и не
публикуемый, — цена не по задаче P3/S. Сделан первый вариант: проверка имён,
`docs/scripts/readme_snippets.py`, рядом с `backlog_index.py` и тем же шагом CI.

**Проверка нашла дефект на первом же прогоне.** `kompot-studio/README.md` показывал
`samples = showcaseComponents().map { wireTypeOf(it) to it }`, а `wireTypeOf` не существует нигде:
в клиенте есть `internal fun KompotComponent.wireType()`, публичного способа получить проводное имя
у тулкита нет. Читатель, скопировавший строку, получил бы unresolved reference. Строка переписана
на то, что делают собственные тесты студии, — пару с явным проводным именем. Публичный `wireTypeOf`
не заводился: это вопрос про API, а не про документацию.

**Что проверка ловит и чего не ловит — записано в ней самой**, а не только здесь: пропавшее имя и
несуществующую координату модуля ловит; изменение сигнатуры — нет; совпадение (`registry` в примере
проходит, потому что где-то в исходниках есть `val registry`) — тоже нет. И она **печатает, о чём
промолчала**: четыре блока из 22 не дали ни одного проверяемого имени, и это видно в выводе каждого
прогона, а не за флагом.

**Два бага в самой проверке нашлись контролями, а не чтением.**

* Снятие `//`-комментариев до строковых литералов съедало половину `"http://localhost:5000"`, и
  `http` уезжал в проверку как имя. Порядок в `strip_noise` теперь обратный, с объяснением.
* Снятие меток именованных аргументов до разбора локальных объявлений превращало
  `val schemas = KompotSpec.generateAll(…)` в `val  KompotSpec…`, и `KompotSpec` записывался в
  локальные — то есть переставал проверяться молча. Поймала самопроверка: она ждёт ровно одно
  ненайденное имя на фикстуре и получила ноль.

**Три положительных контроля прогнаны, каждый красный:**

| мутация | что сказала проверка |
|---|---|
| `kompotVisiblePlaceholderRenderers` переименован в исходнике | `kompot-client/README.md, блок 4: имя ... не объявлено` |
| координата в README изменена на `kompot-corr` | `такого модуля в сборке нет` |
| регулярка блоков сломана | `в файле есть ```kotlin, а разбор не нашёл ни одного блока` |

Третий — про то, ради чего написана самопроверка: сломанный разбор даёт ровно тот же ноль находок,
что и репозиторий, в котором всё в порядке.
